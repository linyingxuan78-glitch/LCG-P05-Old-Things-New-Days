# LCG-P05 v0.15.6 — 实际源码可用性与经营事件审查

**审查状态：代码已更新；Godot 4 原生运行、真实画面、键盘/手柄/视障与儿童用户测试均未完成。**

## 1. 本轮核对的事实（不是推测）

- 游戏为 **第一人称 3D Godot 经营原型**。玩家移动、看向货架与按 E 可上架；但进货、选择商品、批量采购、改价、居民报价和结算仍大量依赖经营桌文字菜单。不能称为“纯画面、零文字游戏”。
- 当前可售商品 27 种，9 个实体共用陈列区，6 个顾客 GLB 外观。**没有另一个独立的二维人物立绘库**。顾客可能在较长时间后重复外观；v0.15.6 避免连续两次抽到同一造型。
- 原有顾客有 walk/idle/互动动画控制，但它是否自然、是否穿模、动作是否对上商品仍需要真实 Godot 渲染及实机观察。
- v0.15.5 只有每日需求轮换、每件商品补货量、常规访客买卖/拒绝，以及玩家主动打开的居民收购；不存在独立的稀有营业突发事件系统。本轮新增一次性每日事件及有限还价。
- 社区旧物日软结局已有三幕文本和临时 3D 布景，但**不是完整配音剧情动画、也不是商业游戏 1.0**。

## 2. 本轮已经修改的功能

1. **低频不可预见事件（每天至多一种）**：前两天没有事件，之后每天约 30% 的概率触发。事件日间隔**至少 3 个营业日**，不让高频弹窗打断经营。新事件不会强制动画、全屏闪光或负债处罚。事件种类：
   - Rain / 下雨：顾客预计到店间隔延长约 45%；
   - Delayed delivery / 供货延迟：非基础 SKU 当天可供应量减少 1，最低 0；
   - Neighbour tip / 邻里推荐：顾客预计到店间隔减少约 25%；
   - Donation day / 居民清货：非基础 SKU 当日可供数量增加 1。
   所有事件在新营业日选定一次，连同最近事件、触发日和累计次数保存；重新载入当天不重新抽选。**需求类别轮换依旧是固定顺序，并非全随机**。
2. **顾客对价格提出还价**：从第二天开始；价差不大（买家预算至少为标价约 80%）、有库存、符合约束时，有约 45% 概率出现；每个营业日最多 1 次。玩家自愿接受或坚持原价。接受后仍在收银台成交，实际谈妥价格写入现金、营收与库存；拒绝不会罚款。寄售品不得谈到低于供应商应付金额。菜单打开时营业时间与人物动画暂停。**这是一次轻量互动，不是完整的议价 AI**。
3. **顾客反馈及账本**：记录顾客成交满意、缺货离开、价格超过预算离开的数量，每日汇总，也计入议价/接受次数；顾客不是会读长文本的智能 NPC，反馈仍是事件分类。
4. **顾客外观去重**：使用原有 6 套已记录来源的角色模型，避免两个相邻到访者出现同一个外观。不是新增 6 个人，也没有解决长期重复出现。
5. **图片提示及简洁 HUD**：新绘制 4 个无闪动图示（购物篮、陈列架、顾客成交、营业日），作为 HUD 操作流程提醒，并增加可开关的 `PICTURE GUIDE` 与 `COMPACT HUD`。原有 `LARGER UI TEXT`、`HIGH CONTRAST`、`REDUCED MOTION` 保留。新增原创图示在 `assets/ui_guides/`，逐文件来源见 `licenses/USED_ASSET_PROVENANCE.csv`。

## 3. 仍然不能声称达成的标准

- **没有无文字游戏模式**：英语仍然覆盖大量菜单、商品、报价和教程；图标只能降低认知负担，不能独立完成从进货到通关的所有操作。多语言、语音旁白/朗读、全面图形交互尚未做。
- **没有完成色盲、读写障碍或低龄玩家验收**：已有文字和对比度开关，但仍需要色觉模拟、字体/焦点/导航测试和多样化用户试用。不能保证所有低龄儿童适用。
- **没有通过光敏性安全测试**：本轮新增图示与经营事件都没有闪光机制，旧场景保留柔和品牌淡入；尚未对实际渲染录像执行逐帧闪烁分析。不能用“绝对不会诱发癫痫”这样的断言。
- **没有完整复杂的客诉/不可抗力系统**：目前只有典型价格议价、供需/天气/邻里事件，没有停电、紧急疏散、事故、退款争议、残障顾客路线等高成本系统。避免过度设计，先确保现有循环能正常运行。
- **没有对标完成后的成品质感**：真实人物大小、货架穿模、操作延迟、动画同步、60FPS/低配表现、鼠标手柄适配、 Windows EXE/PCK 完整性都还没通过。

## 4. 设计和安全参考（外部行业建议，不是项目测试证明）

- [Game Accessibility Guidelines — Basic](https://gameaccessibilityguidelines.com/basic/)：操作可重设、文字大小、颜色之外的冗余信息、简洁语言。
- [IGDA Game Accessibility SIG](https://igda-gasig.org/get-involved/sig-initiatives/resources-for-game-developers/sig-guidelines/)：让新玩家在很少步骤内进入游戏；视觉与声音双反馈。
- [W3C WCAG 2.2, 2.3.1](https://www.w3.org/TR/WCAG22/)：频繁闪烁风险参考标准。WCAG 是网页标准，可为游戏静态或视频内容提供风险筛查框架；不等于通过游戏医学认证。
- [Epilepsy Foundation — Photosensitivity](https://www.epilepsy.com/what-is-epilepsy/seizure-triggers/photosensitivity)：闪光及纹理风险需谨慎控制。

## 5. 游戏开发与验收分开，但不可完全割裂

- 开发阶段允许继续扩充玩法，不必每一版都进行完整玩家测试。
- 每次提交应进行最少的语法/导入/启动/存档功能冒烟测试，避免错误积累；此环境缺少 Godot，可执行脚本已随工程交付，**尚未在引擎中实际运行**。
- 发行前必须完成原生引擎导入、完整经营闭环、动画/碰撞视觉检查、光敏性风险检查、多语言/非读写能力测试、存档与回档、版权审查，以及脱离源工程的 Windows 独立游戏包测试。

## 6. 优先级（本轮结束后仍须做）

1. 首先在 Godot 4 上导入并启动场景；消除实际脚本解析/导入错误。
2. 把经营桌由 27 行的纯文本商品表改为更接近商店实体操作的图片商品卡；支持图形表示数量和价格。
3. 允许更简单的单键/鼠标交互、控制重映射和真正的键盘焦点流程；添加简体中文/至少一个语言选择。
4. 核实 6 套 NPC 骨骼动画的动作过渡、自然脚步和遮挡；需要时再加入更多统一风格角色。
5. 由测试后经营平衡及留存反馈决定是否增加新事件；不堆叠与玩法无关的自然灾害。

**本记录反映源码与资源状态，不代表已通过 Godot 原生或玩家可用性验收。**
